Why teams use branches: Teams use branches to isolate different features, bug fixes, or experiments away from the main production code. This isolation allows multiple developers to work concurrently on separate tasks without stepping on each other's toes or breaking stable code. Branches enable clean code reviews, structured testing, and safe collaboration through pull requests before merging changes back.
Why add-reflection is a better branch name than test or changes: The name add-reflection is descriptive and explicitly communicates the specific purpose and feature content of the branch. Vague names like test or changes provide zero context to reviewers about what work was actually completed. Clear naming conventions improve team communication and repository organization.
What stays protected when I work on a branch instead of main: When working on a separate branch, the main branch remains stable, clean, and fully protected from unfinished, experimental, or broken code. This ensures that anyone pulling from main always gets a working, reliable version of the application while development happens safely elsewhere.
