What editing a file means: Editing a file means making modifications, additions, or deletions to the text or code within a document in your local workspace. These changes are initially unstaged and exist only in your working directory. You must explicitly stage them before they can be recorded.
What staging a file means: Staging a file means marking specific modifications in your working directory to be included in the next commit using the git add command. It acts as a staging area where you carefully curate which changes are ready to be packaged together. This allows you to review modifications and group related changes logically.
What committing a file means: Committing a file means taking the staged snapshot of your project and permanently recording it in the local Git repository history with a unique hash and commit message. Each commit serves as a secure checkpoint or snapshot of your project at a specific point in time. This makes it easy to track history, revert changes, or collaborate.
Why staging is useful: Staging is useful because it gives you granular control over what goes into a commit, allowing you to bundle only related modifications together instead of committing messy, unfinished work. It enables you to review your changes line by line using git status and git diff before saving them permanently. This results in a cleaner, more understandable project history.
